# Farm L route with the camera pointing along the direction of motion: test protocol, written 7 Nov 2026, before the run

**Question.** All Farm runs so far (generation 1 and F5 to F24) used the generation-1 rig, whose camera looks sideways (to the robot's right). Does F24 on the same L route change when only the camera faces forward? Switch-SLAM's own cameras are forward-looking, so this also removes a rig difference from the Farm comparison.

**Same as the 3 Nov F24 Farm run (F24_Predict_Guard.md section 5).** World (cpr_agriculture_gazebo), route and driver (`waypoint_driver_v4.py`, L (0,0)-(0,-40)-(-40,-40), 0.25 m/s), reset to (0,0,0.2) first, wiggle, driver started after FUSED, F24 environment string, A-LOAM launch with the /switch_fused_pose remap, scoring (`score_fused.py`, Umeyama SE(3), no scale).

**Changed (all announced).** (1) Camera faces forward: Gazebo extras file `husky_sim_extras.urdf.xacro` replaces `husky_velodyne_extra.urdf.xacro`. (2) VINS-Mono extrinsicRotation = [[0,0,1],[-1,0,0],[0,-1,0]] (same matrix as `make_sim_calib.py`; translation, intrinsics, noise values, `estimate_extrinsic 1` unchanged), file `farm_fwd_config.yaml` made by `make_forward_vins_config.py` from the farm config. (3) LiDAR samples set to 440 (`GZ_LIDAR_SAMPLES=440`) because the farm rig used 440. Unknowns that the run cannot separate from (1): the farm camera rate and image format (the extras file gives 20 Hz, 8-bit mono; VINS uses 10 Hz either way) and any difference between the two extras files not visible from the repo (LiDAR height 0.4 m and camera at (0.3,0,0.3) are assumed equal; `make_live_extrinsics.py` reads the real LiDAR mount from tf). The run is stated as "forward camera rig", not "only the camera changed".

**Precondition (FC-P0, else void, not adjusted):** `rostopic hz` shows /imu/data about 200 Hz, /camera/image_raw about 20 Hz, /velodyne_points about 10 Hz, and VINS-Mono initialises in the wiggle (new rows in vins_result_no_loop.csv).

**Reading rules (fixed now).** Reference = the 3 Nov F24 run on the sideways rig (fused 0.657 / 0.897, A-LOAM output 0.509 / 0.967, VINS-Mono alone 2.067 / 3.306, VINS path 9.1 % short). Reported: the same three rows for the new run. One run supports no claim: a difference is called a hint only if VINS-alone differs by more than 50 % from 2.067 or fused by more than 0.2 m from 0.657; otherwise "no visible difference at n = 1". The Farm rule (0.38 / 1.10) is reported but this run is not a re-test of it. Nothing is changed after the number; if VINS fails to initialise or the driver sticks, the run is reported as such and a re-run is announced.
